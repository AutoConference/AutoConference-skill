% With ONE metric (P7 had several): the column groups are condition families
% (benchmarks, datasets), the columns within a group are conditions, and the
% `Scenario` multirow becomes the arm family (Baselines / Ours). Both S10 and
% S21 arrived at this mapping independently; use it rather than inventing one.
%
% Reporting uncertainty (references/table-grammar.md, "Reporting
% uncertainty" -- read that section before filling this in): every data
% cell, for every arm, carries `mean [lo, hi]`, lo/hi = min/max of that arm's
% own per_split[condition]['values'] -- bracket, never `mean $\pm$ std`,
% since the range is observed and generally asymmetric. This is the
% tightest-by-construction of the six grammars (a two-level header AND
% vertical rules competing for the same width), yet both real draws (S10 at
% 4 data columns, S21 at 6 with a vertical-rule-separated Navigation group)
% fit the full per-cell treatment at this grammar's default 7.5pt with room
% to spare after \acfit -- see the delivery report's render checks. Treat
% that as validated headroom, not a promise: a group-rules table with MORE
% groups or metrics than S21's should re-check the rendered page before
% assuming it also fits, and drop a column (never shrink the whole table)
% if it does not. If this grammar carries a genuine Average/Overall column
% (S21's does), that one column stays a point estimate: its `std` is spread
% ACROSS conditions, not repeated-run noise.
