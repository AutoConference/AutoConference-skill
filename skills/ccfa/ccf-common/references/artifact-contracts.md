# CCFA Artifact Contracts

These contracts prevent CCFA skills from overwriting each other's work. Read broadly, write narrowly.

## Canonical Artifact And Overwrite Policy

This overwrite policy applies to intermediate artifacts generated by CCFA skills. It does not itself authorize overwriting immutable user inputs, user-managed source history, submitted packages, raw measurements, or externally retained evidence. Necessary generated intermediates may be kept when they support continuation, reproducibility, or an editable deliverable, but each purpose uses one canonical path. When a new generated revision supersedes the previous one, update that canonical file in place instead of creating `v2`, `revised`, `final-final`, date-stamped, timestamped, `_attempts`, or backup copies. Use repository history for rollback when version control is available.

Apply these rules across the family:

1. Resolve the canonical target before writing. Reuse the user's existing file only when the user asks for in-place revision; otherwise apply the canonical-path rule only to skill-generated intermediates and deliverables.
2. Write atomically when practical, then remove any temporary file. Temporary files are not deliverables.
3. Keep one canonical file for each requested format. For example, `paper.tex`, `paper.pdf`, `figure.svg`, `figure.pdf`, and `figure.pptx` may coexist because they are distinct deliverables, but repeated generations replace the matching file.
4. Maintain one canonical ledger and update its rows in place. Store round, version, status, and evidence in columns rather than creating one ledger per round.
5. Retain a generated intermediate only when it is necessary for continuation, reproducibility, editable reconstruction, or a requested audit trail. Keep one current copy and overwrite it on the next iteration. Do not retain redundant prompts, critique passes, render attempts, reviewer-role scratch files, or failed generations unless the user explicitly asks to inspect them.
6. Do not apply overwrite-in-place to immutable user inputs, raw experimental measurements, submitted archival packages, recurring monitoring history, or externally required audit evidence. These are evidence, not disposable process files.
7. A user request for snapshots, alternatives, an audit trail, or several named variants overrides the single-artifact default, but every retained variant must have a stated purpose.

| Artifact | Primary owner | Contract |
| --- | --- | --- |
| `humanization-warnings.md` | `ccf-humanization`, user | Single canonical warning record updated in place when the user asks to persist warnings. It stores advisory/blocking concerns that were not inserted into manuscript, experiment, code, table, or configuration files. Each record states that no artifact change was made for the warning; edits require explicit user approval. |
| `ccfa.yaml` | `ccf-project-scaffolder`, `ccf-pipeline-orchestrator` | Scaffold creates it; orchestrator updates stage/gate state. Other skills may read and propose updates. |
| `literature-monitor/*.md`, `output/literature-monitor/*` | `ccf-literature-monitor` | Stores dated monitoring reports, overlap flags, and watch summaries. Literature searcher may deep-retrieve flagged papers; reviewer/optimizer may use the flags for score or rescue decisions. |
| `literature-search-*/papers.md`, `papers.csv`, `search-notes.md`, `idea-grounding.md` | `ccf-literature-searcher` | Searcher owns verified sources, screening notes, clusters, and the optional compact idea-grounding packet. Idea optimizer may read the packet and create new idea plans, but must not rewrite source evidence or turn inferred gaps into sourced facts. |
| `manuscript/*.tex` | `ccf-paper-writer` | Review and audit skills suggest edits; writing changes route back to paper writer unless user explicitly authorizes otherwise. |
| `references/*.bib` | `ccf-integrity-auditor` | Integrity auditor verifies existing entries; literature searcher proposes new candidates. |
| `experiments/results.*` | user, `ccf-experiment-designer` | Figure/table and integrity skills read supplied numbers only. |
| `figures/*`, `tables/*` | `ccf-experiment-designer`, `ccf-visual-composer` | Experiment designer owns evidence/result content and real values; visual composer owns plotting code, method/architecture diagram composition, palette, panel/table layout, caption placement, manuscript integration, editable vector reconstruction, and render QA. Data and depicted method components must be real. |
| `visual-composer/*` | `ccf-visual-composer` | Stores only requested canonical deliverables and reusable source artifacts, such as plotting code, the current architecture specification, the current raster draft, editable SVG/PPTX, and derived vector PDF. Repeated generation overwrites the matching canonical file. Keep a QA record or prompt only when the user requests it or it is needed to reproduce the final deliverable; do not retain visual iteration logs or render-attempt folders by default. It must not become a hidden source of invented numbers, modules, labels, or flows. |
| `ccfa-review-reports/<paper-slug>-<venue>-review.md` | `ccf-paper-reviewer`, user | Canonical review report. Independent reviews and version comparisons overwrite this file unless the user requests snapshots. Store the review date and compared manuscript versions inside the report, not in the filename. |
| `reviews/revision-ledger.md` | `ccf-rebuttal-writer` | Single canonical ledger updated in place. Tracks reviewer comment, first-seen version, issue origin, response promise, manuscript action, affected score dimension, and status across rounds. |
| `submission/*` | `ccf-submission-checker` | Stores build, anonymity, page, metadata, and policy readiness results. |
| `artifact/*` | `ccf-submission-checker` | Tracks code/data/model release and reproducibility package status. |
| `talk/*` | `ccf-paper-writer` | Presentation outputs only; not submission evidence. |
| `assets/ccfa-skills-*.svg` | `ccf-skill-forger` | Generated by `tools/build_ccfa_diagrams.py`; must pass browser screenshot QA, not only XML parsing. |
| governance docs | `ccf-common`, `ccf-skill-forger` | Routing, naming, trigger registry, source registry, validation, and policy documents. |
